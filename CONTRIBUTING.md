# Contributing to SyncWatcher

Thank you for your interest in improving SyncWatcher.

## External pull request policy

SyncWatcher does not currently accept pull requests or patch submissions from external contributors. Please do not open a pull request for a bug fix, feature, documentation change, translation, or other contribution.

Please use [GitHub Issues](https://github.com/studiojin-dev/SyncWatcher/issues) to report reproducible bugs or propose focused features. Use [GitHub Discussions](https://github.com/studiojin-dev/SyncWatcher/discussions) for support questions and early ideas.

This policy does not limit your rights under [Apache License 2.0](./LICENSE) to fork, modify, or redistribute the licensed Work. It only describes what StudioJin currently accepts for inclusion in the official SyncWatcher repository.

## Reporting bugs and requesting features

- Search existing issues and discussions before opening a duplicate.
- Use the provided bug-report or feature-request issue form.
- Include the SyncWatcher version, distribution channel, macOS version, and focused reproduction steps when reporting a bug.
- Do not include credentials, signing material, personal data, private paths, file contents, or unredacted logs.
- Report security vulnerabilities privately as described in [SECURITY.md](./SECURITY.md), not in a public issue or discussion.

## Rights in issue content

Opening an issue or discussion does not transfer ownership of your original material. Do not attach third-party code, images, logs, or other material unless you have the right to share it and provide any required attribution and license information.

## Brand assets

StudioJin brand assets are not licensed under Apache-2.0. Forks must follow [TRADEMARKS.md](./TRADEMARKS.md) and [BRAND_ASSETS.md](./BRAND_ASSETS.md), including using their own project name and application icon.
